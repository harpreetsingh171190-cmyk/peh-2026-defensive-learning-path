# 35. Threat Modeling and Secure Design

## Outcomes
- Identify assets, trust boundaries, entry points, and abuse cases.
- Use a lightweight STRIDE-style review without treating a checklist as proof of security.
- Turn risks into prioritized mitigations and tests.

## Exercise: threat-model a local notes API
Use a fictional/local-only app with dummy notes. Draw:
1. User/browser, API, database, logging, and backup components.
2. Trust boundaries and data flows.
3. Assets: session tokens, notes, admin functions, backups.
4. Threats: spoofing, tampering, repudiation, information disclosure, denial of service, elevation of privilege.
5. Mitigations and verification tests.

## Deliverable
Save `threat-model.md` with scope, diagram, assumptions, threat table, mitigations, residual risks, and owner. Never include real credentials or personal data.

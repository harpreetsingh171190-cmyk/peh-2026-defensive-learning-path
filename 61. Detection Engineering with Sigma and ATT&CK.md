# 61. Detection Engineering with Sigma and ATT&CK

## Learning goals
Translate a defensive hypothesis into a testable detection, map it to MITRE ATT&CK carefully, and measure false positives.

## Detection lifecycle
1. State the behavior and threat model in plain language.
2. Identify required telemetry and confirm it is collected lawfully.
3. Write a vendor-neutral rule or query using synthetic sample events.
4. Test positive, negative, edge, and malformed cases.
5. Record expected alert fields, severity rationale, and response steps.
6. Measure noise and tune with documented exceptions—not broad blind exclusions.
7. Version-control the rule, peer-review changes, and schedule retesting.

## Example hypothesis
“Alert when a privileged account is created outside the approved change window.” Required fields might include event time, actor, target account, host, and change ticket. Exact event IDs vary by platform; validate against official vendor documentation.

## Exercise
Create five synthetic events: approved admin creation, unapproved admin creation, ordinary user creation, missing actor field, and duplicate event. Describe which should alert and why.

## Quality measures
Coverage, precision, false-positive rate, time to triage, telemetry health, and documented blind spots. A rule mapped to ATT&CK is not proof that all technique variants are detected.

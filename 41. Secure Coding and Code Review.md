# 41. Secure Coding and Code Review

## Learning outcomes
- Review code for input validation, authorization, unsafe deserialization, secrets, and error leakage.
- Separate a bug from an exploitable vulnerability; document evidence and assumptions.
- Add regression tests for fixes.

## Review sequence
1. Read the feature and identify sensitive assets.
2. Trace untrusted input to sensitive operations.
3. Check authentication and authorization separately.
4. Check validation at trust boundaries; prefer allowlists and typed schemas.
5. Check secret handling, logging, error messages, and dependency use.
6. Write a minimal reproducer in a local test environment.
7. Fix, add a regression test, and verify the fix.

## Exercise
Review a small application you own. Make a table with: file/line, input, security boundary, possible impact, evidence, fix, regression test. Use synthetic data only.

## Common review questions
- Is authorization enforced on the server for every object?
- Can users access another user's records by changing an identifier?
- Are secrets committed, logged, or included in screenshots?
- Are errors exposing stack traces or internal paths?
- Are dependencies pinned and maintained?

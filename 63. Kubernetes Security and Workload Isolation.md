# 63. Kubernetes Security and Workload Isolation

## Outcomes
- Explain the control plane, nodes, pods, services, namespaces and RBAC.
- Review workload permissions and reduce container privileges.
- Create a safe review checklist for a cluster you administer.

## Core controls
1. Use supported Kubernetes versions and apply security updates through change control.
2. Use namespace separation, least-privilege RBAC and dedicated service accounts.
3. Disable service-account token mounting when a workload does not need API access.
4. Apply Pod Security Standards; avoid privileged containers, host networking and unnecessary hostPath mounts.
5. Set resource requests/limits, read-only root filesystems where practical, and drop unnecessary Linux capabilities.
6. Restrict ingress and egress with network policies; verify that the CNI actually enforces them.
7. Store secrets in approved secret-management systems, restrict access and rotate them. Never commit real secrets to manifests.
8. Enable audit logs and protect them from modification.

## Safe lab exercise
Use a disposable local cluster or a provided training environment. Inspect only resources in your own namespace. Record the control, evidence, risk and remediation; do not test shared clusters without written scope.

## Deliverable
A one-page cluster hardening review with findings classified by impact, likelihood and business context.

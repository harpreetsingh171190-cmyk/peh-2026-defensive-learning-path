# 62. Security Review for AI Applications

## Learning goals
Assess AI-enabled features for data leakage, prompt injection, unsafe tool use, insecure output handling, and excessive privileges.

## Review checklist
- Define what data the model may receive and retain; minimize sensitive inputs.
- Treat user prompts, retrieved documents, and tool outputs as untrusted data.
- Keep authorization decisions in trusted application code, not model instructions.
- Use explicit tool allowlists, narrow schemas, and per-action authorization checks.
- Require human confirmation for consequential or irreversible actions.
- Validate model output before rendering, executing, or passing it to another system.
- Separate tenants and enforce access controls on retrieval results.
- Protect API keys with secret management and rotate them when exposed.
- Test prompt injection, data exfiltration attempts, refusal bypass, malformed outputs, and denial-of-service scenarios in a sandbox.
- Log security-relevant metadata while avoiding unnecessary prompt or personal-data retention.

## Exercise
Review a fictional assistant that can search documents and send email. Identify how an untrusted document could try to induce an email action. Design a control where the application checks recipient, user permission, and explicit confirmation independently of model text.

## Deliverable
A threat model with assets, trust boundaries, abuse cases, mitigations, test cases, and residual risks.

## Important
Do not upload confidential data to public AI services without organizational approval. Follow current provider documentation and applicable privacy requirements.

# 50. AI and LLM Application Security

## Threat areas
- Prompt injection through user input or retrieved documents.
- Sensitive data exposure in prompts, logs, traces or model responses.
- Excessive agency when a model can call tools or perform actions.
- Weak authorization around retrieval, plugins, APIs and files.
- Unsafe output handling, insecure deserialization and dependency risks.
- Denial of service and unexpected cost from oversized requests.

## Safer design
1. Treat model output and retrieved content as untrusted data.
2. Enforce authorization in application code, not in the prompt alone.
3. Give tools narrow schemas and least-privilege credentials.
4. Require human confirmation for high-impact or irreversible actions.
5. Separate trusted instructions from untrusted documents and preserve source boundaries.
6. Minimize sensitive data; redact logs and define retention.
7. Test refusal, access-control and data-isolation behavior with synthetic data.
8. Monitor usage, errors, costs and suspicious tool-call patterns.

## Exercise
Build a local toy FAQ app with no real secrets or external tool access. Write tests proving that one test user cannot retrieve another test user's synthetic records. Treat this as an application authorization test, not as a guarantee that a model is secure.

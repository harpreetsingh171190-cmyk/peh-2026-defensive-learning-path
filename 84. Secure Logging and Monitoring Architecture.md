# Module 84 — Secure Logging and Monitoring Architecture

## Goal
Design logging that supports detection, response and audits without leaking secrets.

## Design checklist
- [ ] Define what must be logged: authentication, authorization changes, admin actions, errors, data export.
- [ ] Never log passwords, tokens, keys or full payment/personal data; mask at the source.
- [ ] Central, access-controlled, tamper-evident storage with retention rules.
- [ ] Synchronized UTC time and consistent fields (see Module 74).
- [ ] Alerts mapped to runbooks with owners and escalation paths.
- [ ] Monitor the monitoring: alert when log sources go silent.

## Lab
Sketch a data-flow diagram for a fictional web app showing log sources, collector, storage, detections and responders. Mark trust boundaries and who can read or alter logs.

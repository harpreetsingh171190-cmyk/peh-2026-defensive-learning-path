# Module 68 — Zero Trust and Network Segmentation

## Outcomes
- Explain verify-explicitly, least privilege, and assume-breach.
- Design simple trust zones for a small lab.
- Validate segmentation using approved, low-impact checks.

## Core concepts
Zero Trust is an architecture approach, not a product. Access decisions should consider identity, device posture, resource sensitivity, and context. Network location alone is not proof of trust.

## Lab: draw a safe segmentation plan
Use a diagram or table with these zones:
1. Admin workstation
2. User devices
3. Application services
4. Data store
5. Monitoring and backup

For every allowed connection, record source, destination, protocol, business reason, owner, and expiry/review date. Deny everything else by default where operationally practical.

## Validation checklist
- [ ] Management interfaces are not exposed to user or guest networks.
- [ ] Service-to-service access is explicitly documented.
- [ ] Logs capture denied and privileged access where appropriate.
- [ ] Emergency access is controlled, monitored, and periodically tested.
- [ ] Rules have owners and review dates.

## Deliverable
A one-page trust-zone diagram and a table of five example allow rules. Use a fictional environment; do not probe networks without authorization.

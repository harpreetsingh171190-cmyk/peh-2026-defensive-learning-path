# 47. Standards and Official References

Use the current edition shown on each official site. Standards and project guidance change; check publication dates and version numbers before relying on them.

- **OWASP Web Security Testing Guide (WSTG):** https://owasp.org/www-project-web-security-testing-guide/
- **OWASP Application Security Verification Standard (ASVS):** https://owasp.org/www-project-application-security-verification-standard/
- **OWASP API Security Project:** https://owasp.org/www-project-api-security/
- **OWASP Top 10 for LLM Applications:** https://owasp.org/www-project-top-10-for-large-language-model-applications/
- **NIST Secure Software Development Framework (SSDF):** https://csrc.nist.gov/Projects/ssdf
- **NIST Cybersecurity Framework:** https://www.nist.gov/cyberframework
- **MITRE ATT&CK:** https://attack.mitre.org/
- **CISA Secure by Design:** https://www.cisa.gov/securebydesign
- **Android security guidance:** https://developer.android.com/privacy-and-security
- **GitHub Actions security hardening:** https://docs.github.com/en/actions/security-for-github-actions/security-guides/security-hardening-for-github-actions

## How to use references
1. Identify the topic and the edition/version applicable to your work.
2. Read the scope and terminology before selecting a checklist.
3. Adapt controls to your system and threat model.
4. Record the source title, version/date, and access date in the report.
5. Do not claim compliance from a checklist alone; document evidence and gaps.

# 31. AI Security and AI-Assisted Testing (2026)

## Two separate skills
1. **Using AI as a helper:** ask a model to explain a log, suggest test cases, summarize documentation, or review code.
2. **Testing AI-enabled systems:** assess prompt injection, sensitive-data exposure, unsafe tool execution, retrieval poisoning, and over-trust in model output.

AI output is a hypothesis, not evidence. Verify commands, findings, and citations independently.

## Safe AI-assisted workflow
- Use synthetic logs and a local repository.
- Remove credentials, tokens, personal data, internal hostnames, and client evidence before sharing.
- Ask the model for a plan and explainable test cases, then manually review each step.
- Run only approved tests in an isolated environment.
- Record the model/tool version, prompt, output, human verification, and limitations when reproducibility matters.
- Never give an AI agent unrestricted shell, cloud, email, or production access.

## AI application risk areas
- Prompt injection in user content, documents, web pages, or retrieved passages.
- Sensitive information exposed in prompts, logs, embeddings, or generated answers.
- Excessive agency: tools can perform actions beyond the user's intended permissions.
- Insecure output handling: generated text passed to SQL, shell, HTML, or code without validation.
- Weak access control around retrieval and conversation history.
- Denial of service or uncontrolled cost from repeated or oversized requests.
- Poisoned or untrusted training, fine-tuning, plugin, or retrieval data.
- Inadequate evaluation, monitoring, and incident response.

## Defensive design
- Enforce permissions in trusted application code, not in model instructions alone.
- Treat retrieved documents and user prompts as untrusted data.
- Give tools narrow schemas and least-privilege credentials; require human approval for consequential actions.
- Validate and encode outputs before using them in downstream systems.
- Separate secrets from model context and redact sensitive logs.
- Apply rate, token, cost, and time limits.
- Test with a documented evaluation set and review false positives/negatives.
- Monitor tool calls and provide a reliable kill switch.

## Lab exercise
Build a local FAQ chatbot over harmless sample documents. Add a document containing an instruction to ignore the user's question. Verify that the application treats it as untrusted content, cannot access another user's documents, and cannot execute arbitrary tools. Use mock tools only; do not connect this exercise to real accounts or secrets.

## Reporting
Describe the tested model/application, trust boundaries, test case, expected behavior, observed behavior, reproducibility, impact, and a specific mitigation. Do not report a prompt that merely changes wording as a confirmed security vulnerability without demonstrating meaningful impact.

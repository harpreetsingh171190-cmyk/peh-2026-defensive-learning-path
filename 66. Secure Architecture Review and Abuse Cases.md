# 66. Secure Architecture Review and Abuse Cases

## Review workflow
- Identify assets, identities, trust boundaries, data flows and external dependencies.
- Mark where authentication, authorization, validation and audit logging occur.
- Consider abuse cases: account recovery abuse, cross-tenant access, replay, excessive permissions, data export and denial of service.
- Validate that security decisions happen server-side in trusted code.
- Design graceful failure, rate limits, monitoring, recovery and privacy-preserving telemetry.

## Review questions
1. Can a user access another tenant's object by changing an identifier?
2. Can a low-privilege identity invoke an administrative workflow?
3. Are state-changing operations protected against replay and CSRF where relevant?
4. Do logs exclude passwords, session tokens and unnecessary personal data?
5. What happens when the identity provider, secrets manager or audit pipeline is unavailable?

## Exercise
Draw a data-flow diagram for a fictional notes application. Add at least five abuse cases and map each to a preventive control, a detection signal and a test.

## Deliverable
A reviewed diagram and prioritized risk register. Use fictional data only.

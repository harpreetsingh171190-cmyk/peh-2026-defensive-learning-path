# 57. Portfolio, Interview and Final Assessment

## Portfolio project structure
- `README.md`: purpose, setup, scope and limitations.
- `docs/`: threat model, architecture and test plan.
- `labs/`: small reproducible local-only exercises.
- `tests/`: automated tests and expected outcomes.
- `reports/sample-finding.md`: synthetic finding with remediation.
- `LICENSE`: appropriate license for your original work and dependencies.
- `SECURITY.md`: how to report vulnerabilities responsibly.

## Before publishing
- Search for credentials, tokens, personal information and private logs.
- Remove real customer data; use synthetic examples.
- Check licenses and attribution for borrowed code and assets.
- Explain what the tool does not test.
- Include safe defaults, input validation and clear errors.
- Run tests from a clean environment and document the command.
- Never claim a course completion certificate is an industry certification.

## Interview practice prompts
1. Explain authentication versus authorization with a concrete example.
2. Describe how you would verify a finding without accessing data outside scope.
3. Explain how you prioritize a vulnerability.
4. What would you do if a test caused unexpected service impact?
5. How do you protect secrets in a CI pipeline?
6. How would you design a restore test for backups?
7. What limitations should be disclosed in an automated scanner?

## Final capstone
Perform a written, authorized review of a local demo application. Submit scope, threat model, test plan, findings, remediation recommendations, regression tests and a short reflection. Keep all targets and data synthetic or locally controlled.

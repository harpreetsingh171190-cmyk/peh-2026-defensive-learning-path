# 37. Secure Software Supply Chain and SBOM

## Topics
- Direct vs transitive dependencies, lockfiles, provenance, artifact integrity.
- Software Bill of Materials (SBOM) concepts and license/security review.
- Secret scanning, dependency review, signed releases, least-privilege CI.
- Risk-based remediation rather than blindly upgrading every package.

## Practical checklist
- [ ] Commit lockfiles where appropriate.
- [ ] Scan dependencies using a maintained tool and current official docs.
- [ ] Generate an SBOM for a project you own.
- [ ] Review critical/high findings and confirm reachability/exposure.
- [ ] Keep tokens in secret stores; never commit them.
- [ ] Restrict CI permissions and pin third-party actions by immutable reference where practical.
- [ ] Record exceptions, owner, expiry date, and compensating control.

Do not publish internal SBOMs or scan reports if they reveal sensitive architecture.

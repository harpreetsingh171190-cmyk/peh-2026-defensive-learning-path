# 54. Secure CI/CD and Release Engineering

## Learning goals
- Reduce risk in build workflows and deployment identities.
- Protect secrets and artifacts.
- Add security checks without treating tools as proof of security.

## Pipeline guardrails
- Use least-privilege workflow permissions and short-lived credentials where available.
- Protect release branches and environments with review gates.
- Pin third-party workflow actions to reviewed immutable references where practical.
- Keep tokens out of command output, artifacts, caches and test reports.
- Scan dependencies and secrets; triage findings instead of blindly suppressing them.
- Produce an inventory of build artifacts and document provenance.
- Separate untrusted pull-request validation from privileged release workflows.
- Test rollback and recovery procedures.

## Practical lab
In a repository you own, create a workflow that runs unit tests and a dependency audit on pull requests. Use a deliberately fake marker string—not a real credential—to demonstrate how secret scanning works. Review workflow permissions and ensure no deployment secret is available to untrusted contributions.

## Acceptance criteria
- Tests run on pull requests.
- No long-lived admin token is required for ordinary tests.
- Failures are visible and actionable.
- Releases require an explicit approval path.
- A documented rollback process exists.

# 49. Container and Software Supply-Chain Security

## Key concepts
Containers package an application and its dependencies, but they do not automatically make it isolated or secure. Image provenance, dependency health, build permissions, runtime privileges and secrets all matter.

## Defensive checklist
- Prefer minimal, trusted base images and pin versions or digests where practical.
- Scan dependencies and images; review findings rather than blindly suppressing them.
- Run as a non-root user and drop unnecessary Linux capabilities.
- Avoid privileged containers and host filesystem mounts unless strictly needed.
- Never bake credentials into image layers, build arguments or repositories.
- Generate an SBOM where supported and keep build provenance.
- Restrict CI permissions and pin third-party actions to reviewed immutable references.
- Rebuild regularly and define an emergency patch process.

## Exercise
For a container you own, document the base image, runtime user, exposed ports, mounted paths, required secrets and update plan. Use a local test environment; do not inspect or alter third-party images or registries without permission.

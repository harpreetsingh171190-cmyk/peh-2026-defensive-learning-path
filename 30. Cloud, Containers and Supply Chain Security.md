# 30. Cloud, Containers and Software Supply Chain Security

## Learning goals
Recognize common misconfigurations in containers, CI/CD, dependencies, and cloud identity. Perform checks only in your own lab or an authorized environment.

## Container lab hygiene
- Use a disposable VM or a local container runtime.
- Bind lab services to `127.0.0.1` unless remote access is necessary.
- Never mount the host root filesystem or Docker socket into an untrusted container.
- Do not put credentials in Dockerfiles, image layers, Git history, or command-line arguments.
- Use non-root users, minimal base images, read-only filesystems where possible, and explicit resource limits.

## Review checklist
1. Image provenance, pinned tags/digests, supported base image, and vulnerability report.
2. Container user, Linux capabilities, privileged mode, host mounts, network exposure, and secrets.
3. Compose ports: avoid exposing databases and admin interfaces to all network interfaces.
4. Kubernetes basics: RBAC least privilege, namespace boundaries, network policies, pod security, secret encryption, and admission controls.
5. CI/CD: protected branches, short-lived credentials, least-privilege tokens, approval gates, and secret scanning.
6. Dependencies: lockfiles, dependency review, known-vulnerability checks, license review, and reproducible builds.
7. Cloud identity: avoid long-lived access keys; review role trust, public storage, overly broad policies, and audit logs.

## Safe local commands
```bash
docker version
docker compose version
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
```

Only run image scanners on images you are authorized to inspect. Examples of tools to evaluate include Trivy, Grype, Syft, and official cloud-provider security tools. Confirm each tool's current installation instructions in its official documentation.

## Exercise
Create a tiny local web service with no credentials and bind it to `127.0.0.1`. Inspect its image and runtime configuration. Write down three risks, fix them, and capture before/after evidence. Never use real secrets for the exercise.

## Deliverable
A short hardening report covering asset, risk, evidence, remediation, and validation. Distinguish a confirmed vulnerability from a scanner's unverified alert.
